YOUTUBE REACTION VIDEO PIPELINE
Developer Step-by-Step Blueprint
==============================================

PROJECT GOAL
------------
Build a Python/Django-based AI-assisted production pipeline for creating weekly
YouTube reaction/review/criticism videos.

The system should:
- accept a YouTube video URL
- obtain and analyze a timestamped transcript
- select the most useful sections to react to
- screen-record every selected source segment
- generate structured reaction/review/criticism content
- generate intro and outro content
- generate narration using a chosen/cloned narrator voice
- plan and acquire visuals for narration sections
- build a complete video timeline
- add subtitles, music, and audio mixing
- render a final MP4
- run quality control
- optionally prepare and publish the video to YouTube

The system should also provide user control through CRUD actions and an
Approve/Lock workflow at every important stage.

CRUD MODEL
----------
Create = generate/add
Read   = view/preview/listen
Update = edit/change/regenerate/reorder/replace/retry
Delete = remove/discard/archive

Additional workflow states:
- Draft
- Generated
- Needs Review
- Approved
- Locked
- Failed

Core UX principle:

AI GENERATES
    ->
USER REVIEWS
    ->
USER CAN:
- Edit
- Regenerate
- Replace
- Reorder
- Retry
- Remove
    ->
APPROVE / LOCK
    ->
NEXT PIPELINE STAGE

If a locked upstream object is changed, downstream dependent objects should be
marked stale or invalidated and offered for regeneration.

==============================================
PHASE 8 - REACTION BLOCK
==============================================

This is the core original-content unit.

Structure:

SOURCE CLIP
    ->
A. REFRAME
    ->
B. FOCUS
    ->
C. EVALUATE
    ->
D. MINI ESSAY
    ->
E. MINI CONCLUSION
    ->
F. OPTIONAL BRIDGE

----------------------------------------------
A. REFRAME
----------------------------------------------

Purpose:
Repeat/reword what was just heard in clearer, shorter language.

Rules:
- Do not simply repeat the transcript.
- Compress the source speaker's main claim.
- Make the point easy to follow.

User options:
- Generate.
- Read.
- Edit.
- Regenerate.
- Remove.

----------------------------------------------
B. FOCUS
----------------------------------------------

Purpose:
Identify exactly what we want to talk about.

Example logic:
"The important question here is not X. The real issue is Y."

User options:
- Generate.
- Read.
- Change angle.
- Change question.
- Edit.
- Regenerate.
- Remove.

----------------------------------------------
C. EVALUATE
----------------------------------------------

Purpose:
React/review/criticize/agree/challenge.

Suggested reaction types:
- agree
- disagree
- mixed
- fact_check
- context
- counterargument
- clarification
- challenge_assumption
- alternative_interpretation

User options:
- Generate.
- Choose reaction type.
- Edit.
- Change stance.
- Regenerate.
- Remove.

----------------------------------------------
D. MINI ESSAY
----------------------------------------------

Purpose:
Create substantial original content and expand video length.

Possible content:
- explanation
- historical context
- examples
- analogies
- research
- evidence
- counterarguments
- economic implications
- future implications
- alternative interpretations
- recommendations
- original analysis

This should often be the longest part of the Reaction Block.

Suggested length:
45-120 seconds, configurable.

User options:
- Generate.
- Read.
- Edit.
- Expand.
- Shorten.
- Increase depth.
- Reduce depth.
- Add evidence.
- Add examples.
- Change tone.
- Regenerate.
- Remove.

----------------------------------------------
E. MINI CONCLUSION
----------------------------------------------

Purpose:
Summarize the takeaway from this specific segment.

User options:
- Generate.
- Read.
- Edit.
- Regenerate.
- Remove.

----------------------------------------------
F. OPTIONAL BRIDGE
----------------------------------------------

Purpose:
Connect the current Reaction Block naturally to the next source segment.

User options:
- Generate.
- Read.
- Edit.
- Regenerate.
- Remove.

----------------------------------------------
REACTION BLOCK DATA MODEL
----------------------------------------------

Suggested fields:

ReactionBlock
- source_segment
- source_claim
- reframe
- focus
- reaction_type
- reaction_text
- mini_essay_thesis
- mini_essay_script
- conclusion
- bridge
- final_combined_script
- status
- approved_at
- locked_at

Important:
Each subsection must be stored separately.

This allows:
- regenerate only Reframe
- regenerate only Mini Essay
- edit only Conclusion
- preserve approved sections

Recommended duration ratio:
Source clip: ~20 sec
Commentary: ~100 sec

This creates roughly a 5:1 ratio of original commentary to source material.

APPROVE
- Approve/lock each subsection if desired.
- Approve/lock full Reaction Block.

==============================================
DEPENDENCY / INVALIDATION SYSTEM
==============================================

Important architectural rule:

If an approved upstream object changes, dependent downstream objects may no longer
be valid.

Example:

Changing Reaction Block #3 may invalidate:
- Narration audio for Reaction Block #3
- Visual plan
- Visual assets
- Subtitles
- Timeline
- Final render

UX warning example:

"Changing this Reaction Block will invalidate:
- Narration audio
- Visual plan
- Subtitles
- Timeline
- Final render

[Cancel]
[Change and Regenerate Dependencies]"

This dependency system should be built into the data model, not just shown in UI.

MOST IMPORTANT EARLY PROOF OF CONCEPT
==============================================

Before building the complete production studio, create one vertical slice:

One YouTube video
    ->
One selected source segment
    ->
Screen recording
    ->
One complete Reaction Block
    ->
Narrator voice
    ->
2-3 visual assets / B-roll clips
    ->
Subtitles
    ->
Audio mix
    ->
FFmpeg render
    ->
60-120 second finished MP4

If this works well, most of the highest-risk technical assumptions are validated.

After that, scale from:

==============================================
CORE PRODUCT PRINCIPLE
==============================================

The application should not behave like:

Press one button
    ->
AI makes everything
    ->
Finished

It should behave like:

AI generates first draft
    ->
User reviews
    ->
User edits / regenerates / replaces / removes
    ->
User approves / locks
    ->
Next stage
    ->
Final render

This makes the system an AI-assisted Django video production workstation,
not just a one-click generator.
